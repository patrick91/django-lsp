# Completion examples

This page shows completion menus produced by `django-lsp` against the checked-in Django project
fixture. Every menu is generated by opening the displayed source through the real JSON-RPC service
and requesting completion at the illustrated cursor position.

The menu order is the order returned to the editor. Long menus show the first entries and the number
of additional results.

## Model fields

Completion can begin from a partial field name anywhere inside a supported query call.

```django-lsp file=blog/views.py limit=8
from .models import Blog

Blog.objects.filter(
    ti<cursor>
)
```

## Field lookups

After a scalar field and Django's `__` separator, the server offers lookup expressions matching the
typed prefix.

```django-lsp file=blog/views.py limit=8
from .models import Blog

Blog.objects.filter(
    title__i<cursor>
)
```

## Forward relations

Relations can be traversed without importing or executing the Django project.

```django-lsp file=blog/views.py limit=8
from .models import Blog

Blog.objects.filter(
    author__te<cursor>
)
```

## Deep relation paths

Completion continues across multiple related models.

```django-lsp file=blog/views.py limit=8
from .models import Blog

Blog.objects.filter(
    author__team__na<cursor>
)
```

## Many-to-many relations

Many-to-many fields expose the related model's fields and lookup paths.

```django-lsp file=blog/views.py limit=8
from .models import Blog

Blog.objects.filter(
    tags__na<cursor>
)
```

## Reverse relations

Explicit reverse query names are indexed alongside forward relations.

```django-lsp file=blog/views.py limit=8
from .models import Author

Author.objects.filter(
    authored_blogs__ti<cursor>
)
```

## `AUTH_USER_MODEL` relations

Relations declared through `settings.AUTH_USER_MODEL` resolve to the configured user model.

```django-lsp file=blog/views.py limit=8
from .models import Route

Route.objects.filter(
    installer__time<cursor>
)
```
